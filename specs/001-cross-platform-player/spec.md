### 用户故事 1 - 基础视频播放 (优先级: P1)

作为一名 Flutter 开发者，我希望能够在我的应用中轻松集成视频播放功能，只需几行代码就能播放本地或网络视频，而无需了解底层音视频技术细节。

**优先级原因**: 这是播放器的核心价值主张。没有基础播放功能，插件没有任何用途。此故事是所有其他功能的基础。

**独立测试**: 可以通过创建一个最小 Flutter 应用，添加 MangoPlayer 依赖，调用播放 API 播放一个测试视频来完全验证。成功时视频正常播放并显示在屏幕上。

**验收场景**: 

1. **给定** 一个新建的 Flutter 项目已添加 MangoPlayer 依赖, **当** 开发者使用 MangoPlayerController 播放一个 MP4 网络视频 URL 时, **那么** 视频在 500ms 内开始播放，画面流畅无卡顿
2. **给定** MangoPlayer 已初始化, **当** 开发者播放一个本地视频文件时, **那么** 视频正常播放，与网络视频 API 使用方式一致
3. **给定** 视频正在播放, **当** 开发者调用暂停/恢复/停止方法时, **那么** 播放状态立即响应变化
4. **给定** 视频正在播放, **当** 开发者调用 seek 方法跳转到指定位置时, **那么** 播放位置在 200ms 内跳转到目标位置

### 用户故事 2 - 跨平台一致性 (优先级: P1)

作为一名 Flutter 开发者，我希望同一套代码在 Windows、macOS、iOS、Android 上都能正常工作，API 行为完全一致，无需为不同平台编写条件代码。

**优先级原因**: 跨平台一致性是 Flutter 的核心价值，也是章程原则 I 的要求。如果 API 在不同平台行为不一致，将大大增加开发者的维护成本。

**独立测试**: 在所有支持的平台（Windows/macOS/iOS/Android）上运行相同的测试用例，验证 API 返回值和行为完全一致。

**验收场景**: 

1. **给定** 同一份 Flutter 代码, **当** 分别在 Windows、macOS、iOS、Android 上运行时, **那么** 播放行为、API 返回值、事件回调完全一致
2. **给定** 播放器在任一平台上运行, **当** 发生平台特定的行为差异时, **那么** 插件通过统一的错误码或警告机制告知开发者
3. **给定** 开发者使用 MangoPlayer API, **当** 某功能在特定平台不可用时, **那么** API 返回清晰的 "不支持" 状态而非崩溃或静默失败

### 边界情况

- 当网络连接中断时，播放器应暂停播放并显示缓冲状态，网络恢复后自动重试
- 当设备内存不足时，播放器应优雅降级（如降低缓冲区大小）而非崩溃
- 当视频文件损坏或格式错误时，应返回明确的错误信息而非无限加载
- 当应用进入后台时，应根据配置决定是否继续播放音频
- 当同时创建多个播放器实例时，应正确管理资源避免内存泄漏
- 当 seek 到视频末尾时，应正确触发播放完成回调
- 当视频宽高比与容器不匹配时，应提供多种适配模式（填充、适应、裁剪）
- 当自定义模块（解码器/渲染器）实现有错误时，应回退到默认实现并记录错误
- 当注册多个同类型自定义模块时，应有明确的优先级和选择机制
- 当自定义模块性能不达标时，应提供性能警告机制

- **FR-040**: 插件必须确保自定义模块不会破坏跨平台一致性（通过接口契约）

#### 零拷贝渲染（外接纹理）
- **FR-041**: 渲染器必须使用外接纹理（External Texture）方案，减少从 Native 到 Flutter 侧的视频数据拷贝
- **FR-042**: 渲染器必须支持硬件解码器直接输出纹理到 GPU（iOS: CVPixelBuffer → Metal Texture，Android: SurfaceTexture）
- **FR-043**: 渲染器必须通过 Flutter Texture Widget 注册纹理 ID，避免像素数据回传
- **FR-044**: 渲染器必须在各平台实现零拷贝路径（Windows: D3D11 Texture，macOS: Metal Texture，iOS: Metal，Android: OpenGL ES/Vulkan）
- **FR-045**: 渲染器性能必须优于基于像素缓冲区的方案（内存带宽节省 >50%）

### 关键实体

#### 核心实体
- **MangoPlayerController**: 播放器控制器，管理播放生命周期和状态，提供所有播放控制方法
- **MangoPlayerView**: 视频渲染 Widget，负责在 Flutter UI 中显示视频内容
- **PlayerState**: 播放状态枚举，表示播放器当前状态（idle、initializing、ready、playing、paused、completed、error）
- **MediaSource**: 媒体源抽象，封装本地文件路径或网络 URL，支持扩展元数据
- **PlaybackEvent**: 播放事件，包含位置、缓冲进度、状态变化等信息
- **PlayerError**: 错误信息实体，包含错误码、错误消息、平台特定详情

#### 扩展模块接口
- **DataSourceProvider**: 数据源采集器接口，定义如何从不同来源读取媒体数据（文件、网络、内存、加密源等）
- **DecoderProvider**: 解码器接口，定义如何将编码的音视频数据解码为原始帧（可替换为硬件解码器、系统解码器、自定义解码器）
- **RendererProvider**: 渲染器接口，定义如何将解码后的视频帧渲染到屏幕。**核心要求**：使用 Flutter External Texture 实现零拷贝渲染，解码器直接输出 GPU 纹理，避免 Native 到 Flutter 的像素数据拷贝
- **ModuleRegistry**: 模块注册表，管理自定义模块的注册、查询和生命周期

## 技术选型

### 核心播放引擎
- **选定方案**: ijkplayer (基于 ffmpeg)
- **理由**:
  - 跨平台一致性最佳 (ffmpeg 统一解码内核)
  - 已在移动端 (iOS/Android) 成熟验证
  - ijkplayer 核心为 C/C++ 实现，可移植到 Windows/macOS
  - 格式支持最广泛，满足 FR-017~020 要求
- **桌面端策略**: 移植 ijkplayer 到 Windows/macOS，不采用 libmpv 等替代方案

### 渲染方案
- **选定方案**: Flutter External Texture (零拷贝)
- **理由**: 满足 FR-041~045 性能要求，内存带宽节省 >50%

## 假设

基于功能描述和技术选型做出的合理默认假设：

1. **网络条件**: 默认假设用户具有稳定的网络连接（≥5Mbps），网络不稳定情况作为边界情况处理
2. **硬件能力**: 目标设备满足上述平台最低版本要求，具备硬件视频解码能力
3. **视频规格**: 主要优化 1080p 及以下分辨率，4K 支持视硬件能力而定
4. **并发实例**: 默认支持同时运行 2-3 个播放器实例，更多实例可能影响性能
5. **后台播放**: 默认应用进入后台时暂停视频播放，音频是否继续由开发者配置决定

## 范围边界

### 包含在本版本
- Windows、macOS、iOS、Android 平台的完整播放功能
- 本地文件和网络视频播放
- HLS、RTMP、RTSP 流媒体支持
- 默认播放控制 UI 组件
- 基础性能监控

### 不包含在本版本（未来考虑）
- Web 平台完整实现（仅预留接口）
- HarmonyOS 平台实现（仅预留接口）
- DRM 保护内容播放
- 画中画功能
- 字幕加载与显示（可作为后续功能）
- 视频录制功能
- 实时音视频通话功能

## 章程合规性检查

此功能必须符合 `.specify/memory/constitution.md` 中定义的核心原则:

- [x] **跨平台一致性**: API 在 Windows/macOS/iOS/Android 上行为一致，Web/HarmonyOS 返回清晰的不支持状态
- [x] **Native 性能优先**: 满足上述性能指标（启动 <500ms，30fps，内存 <150MB），基于 ijkplayer+External Texture
- [x] **模块化架构**: Controller/View/State 分离，平台实现通过抽象层隔离
- [x] **测试优先开发**: 每个用户故事包含可测试的验收场景
- [x] **文档完整性**: 用户故事和需求描述清晰，API 文档计划明确
- [x] **API 稳定性**: 公共 API 设计支持未来平台扩展而不破坏兼容性
