**平台版本要求**:
- **Android**: API Level 24 (Android 7.0)+

**兼容性约束**: 无现有依赖冲突（绿地项目）

## 3. 技术方案评估

### 方案 A: ijkplayer + ffmpeg + External Texture ✅ (已选定)

- **描述**: 使用 ijkplayer 作为播放内核，ffmpeg 处理解码，通过 Flutter External Texture 实现零拷贝渲染
- **集成方式**: 部分引入 (使用 ijkplayer 核心，包装为 Flutter Plugin)
- **工作量**: **XL** (>1月)
- **优点**:
  - ijkplayer 已在 iOS/Android 上成熟应用 (B站验证)
  - ffmpeg 格式支持最广泛，满足 FR-017~020
  - ijkplayer 核心为 C/C++ 实现，可移植到 Windows/macOS
  - External Texture 实现零拷贝，性能最优 (内存带宽节省 >50%)
- **缺点**:
  - ijkplayer 未官方支持桌面端，需移植工作
  - External Texture 在 4 个平台实现路径各异，集成复杂
- **依赖兼容性**: 兼容（绿地项目无冲突）

**桌面端移植策略**: 
- ijkplayer 核心为 C/C++ + ffmpeg，跨平台编译难度可控
- Windows: 使用 MSVC 编译，D3D11 纹理输出
- macOS: 使用 Clang 编译，Metal 纹理输出
- 参考社区已有的桌面端移植尝试

---

### 方案 B: video_player 插件扩展 ❌ (已否决)

- **描述**: 基于官方 video_player 插件，扩展平台支持
- **集成方式**: 完全引用 + 二次开发
- **工作量**: **M** (1-2周)
- **优点**: Flutter 官方维护，兼容性好
- **缺点**:
  - 桌面端支持不成熟
  - **无法满足模块化扩展需求 (FR-031~040)**
  - 性能不及 Native 播放器
  - **违背章程 II (Native 性能优先)**

**否决理由**: 不满足核心需求和章程要求

---

### 方案 C: 多平台原生播放器 + 统一抽象层 ❌ (已否决)

- **描述**: 各平台使用原生播放器 (AVPlayer/ExoPlayer/Media Foundation)
- **集成方式**: 参考实现
- **工作量**: **L** (2-4周)
- **优点**: 性能最优，利用系统优化
- **缺点**:
  - **跨平台一致性难以保证 (各平台 API 差异大)**
  - 格式支持受限于系统能力
  - **违背章程 I (跨平台一致性)**

**否决理由**: 无法保证跨平台一致性

## 4. 关键技术决策建议

### 决策点 1: 播放内核选择
- **建议**: ijkplayer + ffmpeg
- **理由**: 
  - 跨平台一致性最好 (ffmpeg 是唯一标准)
  - 格式支持最广 (满足 FR-017~020)
  - 已有移动端成熟案例 (B站、爱奇艺等)
  - C/C++ 核心可移植到桌面端

### 决策点 2: 渲染方案
- **建议**: Flutter External Texture (零拷贝)
- **理由**:
  - 满足性能要求 (FR-041~045: 内存带宽节省 >50%)
  - Flutter 官方推荐方案
  - 跨平台 API 统一

### 决策点 3: 桌面端策略
- **建议**: 移植 ijkplayer 到 Windows/macOS
- **理由**:
  - 保证一致性 (符合章程 I)
  - ijkplayer 核心为 C/C++，具备可移植性
  - 不采用 libmpv 等替代方案，保持技术栈统一

### 决策点 4: HarmonyOS 策略
- **建议**: 接口预留 + 占位实现
- **理由**:
  - 优先级低 (P4)，不阻碍主要平台开发
  - 架构层面预留扩展接口
  - 待主要平台稳定后再评估实施
