### 澄清 #1 - 模块化扩展架构
**日期**: 2025-12-19
**提出者**: 用户
**问题**: "我希望采集、解码、渲染这3个模块也是从设计上支持扩展的"

**分析**:
用户希望播放器的核心模块（数据采集、解码、渲染）具备可扩展性，允许高级用户或贡献者替换或扩展这些模块以满足特殊需求。

**澄清结果**:
- 确认需要为三个核心模块定义清晰的接口
- 确认需要支持运行时注册和切换模块实现
- 确认需要提供默认实现和扩展指南

**规范更新**:

#### 新增用户故事
- **US6 - 模块化扩展架构 (P2)**: 支持扩展/替换采集、解码、渲染模块

#### 新增功能需求 (FR-031 到 FR-040)
- FR-031: 定义数据源采集器接口（DataSourceProvider）
- FR-032: 定义解码器接口（DecoderProvider）
- FR-033: 定义渲染器接口（RendererProvider）
- FR-034: 提供默认数据源采集器实现
- FR-035: 提供默认解码器实现（基于 ffmpeg）
- FR-036: 提供默认渲染器实现（基于 WebRTC）
- FR-037: 支持运行时动态注册和切换模块
- FR-038: 统一的错误处理和日志机制
- FR-039: 扩展模块开发指南和示例
- FR-040: 确保自定义模块的跨平台一致性

#### 新增关键实体
- **DataSourceProvider**: 数据源采集器接口
- **DecoderProvider**: 解码器接口
- **RendererProvider**: 渲染器接口
- **ModuleRegistry**: 模块注册表

#### 新增边界情况
- 自定义模块错误时回退到默认实现
- 多个同类型模块的优先级机制
- 自定义模块性能不达标时的警告

#### 新增成功标准
- SC-005: 高级开发者在 2 小时内可实现自定义模块

**影响范围**:
- 架构设计: 高 - 需要在设计阶段定义清晰的模块接口
- 实现复杂度: 中 - 需要实现注册机制和回退逻辑
- 测试范围: 高 - 需要测试模块替换场景和错误处理
- 文档需求: 高 - 需要编写详细的扩展开发指南

**下一步**:
在 `/speckit.plan` 阶段需要重点设计：
1. 三层模块接口的具体契约定义
2. 模块注册和生命周期管理机制
3. 默认实现与自定义实现的切换逻辑
4. 性能监控和错误处理框架

### 澄清 #2 - 外接纹理零拷贝渲染
**日期**: 2025-12-19
**提出者**: 用户
**问题**: "在渲染时为了提高性能，我要求用外接纹理方案实现"

**分析**:
用户明确要求使用外接纹理（External Texture）方案，目标是**减少从 Native 到 Flutter 侧的视频数据拷贝**，实现零拷贝渲染以提升性能。

**澄清结果**:
- 确认使用外接纹理方案实现渲染模块
- 确认需要支持硬件解码器直接输出 GPU 纹理
- 确认需要在所有平台实现零拷贝路径

**规范更新**:

#### 新增功能需求 (FR-041 到 FR-045)
- FR-041: 渲染器使用外接纹理方案，减少 Native 到 Flutter 数据拷贝
- FR-042: 支持硬件解码器直接输出纹理到 GPU（iOS: CVPixelBuffer→Metal, Android: SurfaceTexture）
- FR-043: 通过 Flutter Texture Widget 注册纹理 ID，避免像素数据回传
- FR-044: 各平台实现零拷贝路径（Windows: D3D11, macOS: Metal, iOS: Metal, Android: OpenGL ES/Vulkan）
- FR-045: 性能优于像素缓冲区方案（内存带宽节省 >50%）

#### 更新关键实体
- **RendererProvider**: 强调核心要求为外接纹理零拷贝渲染，解码器直接输出 GPU 纹理

#### 新增性能指标
- **零拷贝渲染效率**: 内存带宽节省 >50%，CPU 占用降低 >30%

**影响范围**:
- 架构设计: 高 - 渲染模块需基于平台纹理 API 设计
- 实现复杂度: 高 - 需要对接各平台图形 API（Metal/D3D11/OpenGL/Vulkan）
- 测试范围: 高 - 需要验证各平台零拷贝路径和性能收益
- 文档需求: 中 - 需要说明外接纹理机制和平台差异

**下一步**:
在 `/speckit.plan` 阶段需要重点设计：
1. 各平台外接纹理实现方案（iOS/Android/Windows/macOS）
2. 硬件解码器与纹理输出的对接机制
3. Flutter Texture Widget 集成方式
4. 性能监控和对比测试方案
